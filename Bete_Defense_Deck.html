Problem Statement

Four structural challenges in Ethiopia's traditional repair market

Bete
🚨 Informal Search & Safety Risks
  • • Zero background or criminal checks on unvetted street technicians
  • • Inviting unverified strangers into private family homes creates safety hazards
  • • Absence of institutional accountability or verified identity records
💰 Arbitrary & Inflated Pricing
  • • No standardized rate cards or preliminary diagnostic baselines
  • • Technicians charge inflated fees on arrival during emergency breakdowns
  • • Unpredictable costs and stressful manual price bargaining
⏳ Severe Scheduling Friction
  • • Customers waste hours making repeated phone calls across the city
  • • High technician no-show rates with zero advance notice
  • • Inefficient geographic matching across Addis Ababa's large subcities
❌ Zero Workmanship Guarantee
  • • Informal cash transactions provide no formal receipts or service history
  • • No warranty or follow-up when completed repairs fail shortly after
  • • Total absence of customer dispute resolution mechanisms

System Workflow & State Machine

Finite state machine governing the complete lifecycle of each repair request

Bete
State 1
Job Created

Customer submits category, description, photos, and subcity. Request status set to 'open'.

State 2
Bids Received

Vetted local technicians inspect photos and submit competitive price quotes in Ethiopian Birr.

State 3
Bid Accepted

Customer accepts bid. Order created; status transitions to 'assigned'; appointment scheduled.

State 4
In Progress

Technician arrives on site, performs diagnosis, and completes repair. Status set to 'active'.

State 5
Closed & Rated

Customer inspects work, settles payment, and rates technician. Status transitions to 'completed'.

Database Design

Mongoose document model enforcing relational integrity across collections

Bete
🗄️ Users Collection
  • • _id: ObjectId (Primary Key)
  • • phone: String (Unique index)
  • • role: 'customer' | 'provider'
  • • fullName: String
  • • subcity: String (Addis Ababa)
🗄️ ProviderProfiles
  • • _id: ObjectId (Primary Key)
  • • userId: Ref(Users)
  • • skills: [String] (Trades)
  • • kebeleIdUrl: String
  • • isVerified: Boolean (Default: false)
🗄️ JobRequests
  • • _id: ObjectId (Primary Key)
  • • customerId: Ref(Users)
  • • category: String
  • • photos: [String]
  • • status: 'open'|'active'|'done'
🗄️ Bids Collection
  • • _id: ObjectId (Primary Key)
  • • jobId: Ref(JobRequests)
  • • providerId: Ref(Users)
  • • amount: Number (ETB)
  • • status: 'pending'|'accepted'
🗄️ Orders Collection
  • • _id: ObjectId (Primary Key)
  • • jobId: Ref(JobRequests)
  • • providerId: Ref(Users)
  • • scheduledAt: Date
  • • status: 'active'|'completed'
🗄️ Reviews Collection
  • • _id: ObjectId (Primary Key)
  • • orderId: Ref(Orders)
  • • customerId: Ref(Users)
  • • providerId: Ref(Users)
  • • rating: Number (1 to 5)

Role-Based Access Control (RBAC)

Security boundaries and permission partitioning across all platform actors

Bete
👤 Customer Permissions
  • • Access to (customer-tabs) route group
  • • Can create, edit, and cancel repair job requests
  • • Can review incoming bids and accept a quote
  • • Can chat with and rate assigned technician

  • • Access to completed jobs ledger and earnings tracker
  • • Restricted: Cannot submit bids until admin approves Kebele ID

Challenges & Engineering Solutions

Key technical hurdles encountered and how they were solved

Bete
Challenge 1
Dual-Role Codebase Architecture

Problem: Managing customer and provider roles in one app without code bloat.
Solution: Implemented Expo Router route groups (customer-tabs) and (provider-tabs) governed by dynamic Zustand role state.

Challenge 2
Real-Time Bidding Overhead

Problem: HTTP polling for new bids drained mobile battery and overloaded server.
Solution: Integrated Socket.io room events triggered by MongoDB document updates for instant, push-based delivery.

Challenge 3
ID Vetting Without National API

Problem: Absence of automated national API registries for background checking.
Solution: Built a dedicated Admin Gateway for manual auditing of uploaded Kebele IDs and TVET diplomas before badge issuance.

Challenge 4
Intermittent Network Latency

Problem: Unreliable 3G/4G connectivity across different Addis Ababa neighborhoods.
Solution: Implemented client-side image downscaling before upload and optimistic UI caching for instant feedback.
